## 🗺️ 阅读路径建议

### 新接手这个项目的人
1. `ARCHITECTURE.md` → 理解全局
2. `API-REFERENCE.md` → 了解接口
3. `DEPLOYMENT.md` → 学会部署
4. `CHANGELOG.md` → 看最近改了什么

### 要做新功能
1. **先明确产品边界**：功能矩阵与档位以 `src/plans.js` 为唯一权威源（开发路线图属方案层，不随本仓库公开）
2. 涉及策略/竞品/PRD 的分析属**方案层**（不在本仓库内，不随开源公开）
3. `ARCHITECTURE.md` → 找对应模块
4. 改完代码 → **同步更新** `CHANGELOG.md` + `API-REFERENCE.md`（如新增端点）+ `ARCHITECTURE.md`（如新增模块）

### 要上线生产
1. `DEPLOYMENT.md` → 按步骤执行
2. `API-REFERENCE.md` → 前端联调

## 📂 文件归属说明

- **本仓库 `docs/`**（随代码版本管理）：**纯实施参考**
  - 放：API 速查 / 架构 / 部署 / 变更记录 / 索引
  - 不放：竞品分析 / 需求记录 / PRD / 开发计划 / 项目复盘 / 流程规范 → 属方案层，不在本仓库

- **方案层目录**（本地独立目录，**不随本仓库公开**）：**先于代码产出**
  - 放：竞品分析 / 技术选型 / 定价调研 / PRD / 开发计划 / 项目复盘 / 流程规范 / 需求记录 / 功能对照
  - 用途：确认后 AI 才写代码

- **角色记忆目录**（本地独立目录，**不随本仓库公开**）：角色记忆、决策日志、变更通知 —— **不重复记**，只放索引

## 🔴 文档维护铁律

1. **任何影响产品行为的代码变更，必须同步更新 `CHANGELOG.md`**（否则后续复盘找不到依据）
2. **新增 API 端点 → 同步更新 `API-REFERENCE.md`**
3. **修改架构/模块 → 同步更新 `ARCHITECTURE.md`**
4. **部署步骤变化 → 同步更新 `DEPLOYMENT.md`**
5. **禁止只在当日工作日志里记变更、不进项目文档**
6. **禁止把 PRD/流程/需求分析塞进 `docs/`**——它们属方案层，方案确定后才落代码、落代码后才同步回 `docs/` 作快照
